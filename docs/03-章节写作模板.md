# 章节写作模板

每章必须使用同一套教学结构，避免变成资料堆叠。

## 标准结构

```markdown
# 第 X 章 章名

## 本章解决什么问题

用 3-5 句话说明本章要解决的真实学习问题。

## 学习完成后应达到的能力

- 可观察目标 1
- 可操作目标 2
- 可解释目标 3

## 必须理解的概念

| 概念 | 简明定义 | 容易误解的点 |
|---|---|---|
| ... | ... | ... |

## 最小可运行实验

### 实验目标

### 前置条件

### 操作步骤

### 正确现象

### 如果失败，先检查什么

## 命令与代码

只放本章必要命令和最小代码。代码要能复制运行，命令要能复现。

## 观察与解释

说明学生应该看什么输出、图、topic、节点、日志或文件。

## 高频错误

| 现象 | 原因 | 修复 |
|---|---|---|
| ... | ... | ... |

## 本章自测

1. 概念题。
2. 命令题。
3. 实验解释题。

## 延伸阅读

- 官方资料
- 开源仓库
- 中文辅助资料
```

## 安装类章节额外结构

安装类章节必须增加以下内容：

- 方法适用人群。
- 前置条件。
- 优点与限制。
- 完整步骤。
- 验证命令。
- 卸载或恢复方法。
- 常见失败原因。
- 是否适合课堂批量部署。

## 写作硬规则

- 先解释概念，再给命令，再观察现象，最后总结错误原因。
- 不能只写“执行下面命令”，必须说明命令改变了什么系统状态。
- 每个抽象概念至少配一个可观察命令或图形界面。
- 每章至少列 3 个高频错误。
- 命令默认使用 Ubuntu 20.04 + Bash。
- ROS 命令默认基于 ROS Noetic。
- 不把 LoongArch64 内容写进主体章节。
